The daemon's spans follow the naming contract sealant and Mend share: `sealantd.<area>.<operation>` in lower snake case, op `sealantd.<area>`, and a short description of its own. Control requests are `sealantd.control.<method in snake case>` (`sealantd.control.write_stdin`, `sealantd.control.runtime_health`), described as what the method does ("write to stdin", "check runtime health"), with the wire name kept in `rpc.method` (`writeStdin`). A container boot is `sealantd.workspace.boot`, and each boot stage is named for what it does (`sealantd.boot.clone_repository`, `sealantd.boot.start_harness`, the runner's `sealantd.vm.start_vmm`), still carrying `sealant.boot.stage`. A process's user lookup is `sealantd.process.resolve_user`, a session's journal `sealantd.session.create_journal`, and attaching to its output `sealantd.session.stream_output`. The egress proxy's admin spans are named by route (`PUT /v1/policy`). Each boot stage now runs from where the stage before it ended, so a boot's stages read as one step after another instead of each starting at the boot's start. Every exported span and error now names a release: a build with no `SENTRY_RELEASE` (a local one) reports a `-dev` release (`sealantd@0.0.0-dev`).
